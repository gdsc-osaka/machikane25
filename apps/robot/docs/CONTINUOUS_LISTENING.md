# 常時リスニングシステム - 使い方ガイド

## 概要

たこまる君の常時リスニングシステムは、**2つのプロセスに分離**されています：

1. **録音デーモン** (`audio_recorder_daemon.py`) - マイク権限が必要
2. **たこまる君本体** (`src/main.py`) - ファイル監視で文字起こし

これにより、macOSのマイク権限の問題を回避できます。

## 仕組み

```
[ターミナル1: 録音デーモン]       [ターミナル2: たこまる君]
         ↓                              ↓
   10秒ごとに録音                  ファイル監視
         ↓                              ↓
音声があればWAV保存  ──────→    新ファイル検出
 (data/shared_audio/)               ↓
                              Whisper文字起こし
                                     ↓
                                  応答生成
```

## 設定のカスタマイズ

### 録音デーモンの設定

[audio_recorder_daemon.py](../audio_recorder_daemon.py)の冒頭で設定を変更できます：

```python
# 設定
SHARED_AUDIO_DIR = Path("data/shared_audio")
RECORDING_DURATION = 10  # 録音時間（秒）
DEVICE_ID = 0  # オーディオデバイスID
SILENCE_THRESHOLD = 0.01  # 音声判定の閾値
```

**RECORDING_DURATION**:
- デフォルト: 10秒
- 短くすると反応が速くなるが、長い発話が途切れる
- 長くすると確実だが、レスポンスが遅くなる

**DEVICE_ID**:
- デフォルト: 0（BlackHole 2ch）
- 別のマイクを使う場合は、`python3 check_audio_devices.py` で確認

**SILENCE_THRESHOLD**:
- デフォルト: 0.01
- 小さくすると小さな音も拾う（ノイズも拾いやすい）
- 大きくすると大きな音のみ拾う（音声を見逃す可能性）

---

### たこまる君の設定

[src/agent/brain.py](../src/agent/brain.py#L183-L188)で設定を変更できます：

```python
self.continuous_listener = FileBasedListener(
    on_speech_detected=self._on_speech_detected,
    model_size="medium",  # Whisperモデルサイズ
    shared_audio_dir="data/shared_audio",  # 共有ディレクトリ
    check_interval=1.0  # ファイルチェック間隔（秒）
)
```

**model_size**:
- `base`: 最速、精度低
- `small`: 高速、精度中
- `medium`: バランス型（推奨）
- `large`: 最高精度、遅い

**check_interval**:
- デフォルト: 1.0秒
- 小さくすると反応が速くなる
- 大きくするとCPU負荷が減る

## トラブルシューティング

### 問題1: 録音デーモンで音声が検出されない

**症状**: RMS音量が常に 0.0000

**確認**:
```bash
# オーディオデバイスを確認
python3 check_audio_devices.py

# デフォルト入力デバイスが正しいか確認
system_profiler SPAudioDataType | grep -A 5 "Default Input"
```

**解決策**:
- システム設定 → サウンド → 入力デバイスを確認
- BlackHole 2chまたは正しいマイクが選択されているか確認

---

### 問題2: たこまる君が音声ファイルを検出しない

**症状**: `🆕 新しい音声ファイル検出` が表示されない

**確認**:
```bash
# 共有ディレクトリにファイルがあるか確認
ls -l data/shared_audio/
```

**解決策**:
- 録音デーモンが正常に動作しているか確認
- 共有ディレクトリのパスが正しいか確認
- ディレクトリの権限を確認

---

### 問題3: 文字起こし結果が空

**症状**: `⚠️ 文字起こし結果が空`

**原因**:
- 音声が小さすぎる
- ノイズが多い
- 日本語以外の言語

**解決策**:
1. マイク音量を上げる
2. 静かな環境で試す
3. はっきりと話す

---

### 問題4: 処理が遅い

**症状**: 文字起こしに時間がかかる

**解決策**:
1. Whisperモデルを `medium` → `small` に変更
2. GPU版PyTorchをインストール
   ```bash
   pip3 install torch torchvision torchaudio
   ```

## 補足情報

### なぜ2つのプロセスに分離？

macOSでは、アプリケーションがマイクにアクセスするには**ユーザーが直接起動**する必要があります。

- ❌ VSCodeから実行 → マイク権限エラー
- ✅ ターミナルから直接実行 → マイク権限OK

録音デーモンを分離することで：
- 録音デーモンだけをユーザーが直接起動
- たこまる君本体はVSCodeやどこからでも起動可能

### ファイル共有の仕組み

- 録音デーモンが `data/shared_audio/` にWAVファイルを保存
- たこまる君が1秒ごとにディレクトリをスキャン
- 新しいファイルを検出したら文字起こし
- 処理後、ファイルを削除

シンプルで確実な方式です。
